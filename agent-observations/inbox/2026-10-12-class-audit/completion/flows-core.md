## Delivery → sent state → ACK/retry

Created sender loads CREATED1 batches, submits MessageSender tasks, waits indefinitely for executor termination, then processes successful sent-set. Pending sender uses PENDING2 dedicated loader and same send path ([Server:666–713](https://github.com/eabbasiyan-maker/Async-Source/blob/781e6c4c61706a798883818982f72fb8fa53a661/src/com/nozha/async/server/Server.java#L666-L713), [Server:1266–1308](https://github.com/eabbasiyan-maker/Async-Source/blob/781e6c4c61706a798883818982f72fb8fa53a661/src/com/nozha/async/server/Server.java#L1266-L1308)). Per-task unexpected failures can be captured in ignored submitted Futures; completion of batch wait alone does not prove every message was delivered.

MessageSender first resolves tracker; otherwise acquires receiver pool client; QueueClient is released immediately, ordinary client in finally. Missing client can persist active **nonbinary** NOT_SENT or update created/pending offline status. Found client emits BeforeSendLog, can write PENDING DB state before active send, arms timeout, makes outbound payload, calls client.sendMessage, cancels timer, emits AfterSendLog, then records successful set/normal sent state ([Server:751–889](https://github.com/eabbasiyan-maker/Async-Source/blob/781e6c4c61706a798883818982f72fb8fa53a661/src/com/nozha/async/server/Server.java#L751-L889)). BeforeSendLog proves pre-send stage; AfterSendLog proves return from client.sendMessage, **not recipient ACK**. Timer interrupt is not proof that transport write stopped; HTTP timeout also destroys client status3 ([Server:892–908](https://github.com/eabbasiyan-maker/Async-Source/blob/781e6c4c61706a798883818982f72fb8fa53a661/src/com/nozha/async/server/Server.java#L892-L908)).
